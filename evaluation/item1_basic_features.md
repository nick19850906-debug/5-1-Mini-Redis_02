# 항목 1: 기본 기능 동작 (5문항 · 초간단 정리)

> 저장, 조회, 메모리 제한, 유통기한, 에러 출력이 제대로 되는지 확인하는 항목입니다.

---

## 1-1. String 타입 기본 동작 (`SET`, `GET`, `DEL`, `EXISTS`, `DBSIZE`, `KEYS`)
- **한 줄 정답**: 네, 6가지 기본 명령어가 모두 정상 동작하며 따옴표(`"Kim Min"`) 안의 공백도 한 단어로 잘 처리합니다.
- **일상 비유**: 도서관 책 관리 기본 업무 6가지입니다. 책 넣기(`SET`), 찾기(`GET`), 버리기(`DEL`), 있는지 보기(`EXISTS`), 몇 권인지 세기(`DBSIZE`), 책 제목 다 보기(`KEYS`).
- **면접용 쉬운 답변 (그대로 읽기)**:  
  > "`string_commands.py`에 6개 명령을 분리해 구현했습니다. 저장·조회·삭제 모두 직접 만든 해시맵과 줄 서기 리스트를 동시에 업데이트하고, 명령을 실행하기 전에 만료된 키부터 청소해서 죽은 키가 개수나 목록에 남지 않게 했습니다."

---

## 1-2. LRU 자동 제거 (`maxmemory` 초과 시 가장 오래된 키 제거)
- **한 줄 정답**: 네, `maxmemory` 한도를 넘기면 가장 오랫동안 안 쓴 키(줄 맨 뒤 `tail`)부터 자동으로 버립니다.
- **일상 비유**: **좁은 책상**입니다. 책상이 꽉 찼는데 새 책이 들어오면, **가장 오래 안 펼쳐 본 맨 아래 책**부터 서랍으로 치워 자리를 만듭니다. 방금 다시 본 책(`GET`)은 맨 위로 올라가서 안 버려집니다.
- **면접용 쉬운 답변 (그대로 읽기)**:  
  > "`CONFIG SET maxmemory`로 제한을 걸어두면, `SET`할 때 한도를 넘은 만큼 줄의 맨 뒤(`tail`)에 있는 가장 오래된 키부터 자동으로 지웁니다. 반대로 `GET`으로 꺼내 본 키는 줄 맨 앞(`head`)으로 옮겨서 지워지지 않게 보호합니다."

---

## 1-3. 메모리 정보 확인 (`INFO memory`)
- **한 줄 정답**: 네, 현재 사용량(`used_memory`), 최대 한도(`maxmemory`), 쫓겨난 개수(`evicted_keys`) 3줄을 규칙대로 정확히 보여 줍니다.
- **일상 비유**: **창고 현황판**입니다. 지금 쌓인 짐 무게(`키 글자 바이트 + 값 글자 바이트`), 창고 최대 무게, 꽉 차서 밖으로 내보낸 짐 개수를 보여 줍니다.
- **면접용 쉬운 답변 (그대로 읽기)**:  
  > "`used_memory`는 저장된 모든 키와 값의 UTF-8 바이트 길이를 더한 값입니다. 새 키를 넣으면 더하고, 삭제하거나 만료되면 빼며, `evicted_keys`는 오직 메모리 초과 때문에 강제로 쫓겨났을 때만 1씩 올립니다."

---

## 1-4. TTL 관리 (`EXPIRE` / `TTL` 만료 규칙)
- **한 줄 정답**: 네, 만료 시간을 설정(`EXPIRE`)하고 남은 시간(`TTL`)을 보며, 시간이 지나면 자동으로 지워집니다.
- **일상 비유**: **우유 유통기한 스티커**입니다. 3초 뒤 버리라고 적어 두고(`EXPIRE` → `1`), 남은 시간을 물어보면 알려 줍니다(`TTL`). 없는 키는 `-2`, 기한이 없는 키는 `-1`을 돌려주고, 시간이 지나면 버린 뒤 없는 키(`-2`, `(nil)`)로 처리합니다.
- **면접용 쉬운 답변 (그대로 읽기)**:  
  > "`EXPIRE`로 만료 시각을 정해 최소 힙에 등록하고, 명령이 들어올 때마다 시간이 지난 키를 먼저 지웁니다. 없는 키는 `-2`, 기한이 없으면 `-1`, `0` 이하로 주면 즉시 삭제, 같은 키를 `SET`으로 덮어쓰면 유통기한도 초기화되는 규칙까지 맞췄습니다."

---

## 1-5. 에러 처리 (잘못된 명령 / 인자 / 정수 / OOM)
- **한 줄 정답**: 네, 이상한 입력이 들어와도 프로그램이 멈추지 않고 Redis 표준 형식인 `(error) ...` 문구를 출력합니다.
- **일상 비유**: **친절한 매장 안내판**입니다. 메뉴에 없는 걸 시키거나, 개수를 틀리거나, 숫자 칸에 글자를 쓰거나, 혼자서도 창고보다 큰 짐을 넣으려(OOM) 하면 규칙에 맞는 안내 문구만 띄우고 다음 주문을 계속 받습니다.
- **면접용 쉬운 답변 (그대로 읽기)**:  
  > "`errors.py`에 표준 에러 문구를 모아두고, 실행 전에 없는 명령어인지, 인자 개수가 맞는지, 숫자가 맞는지 순서대로 검사합니다. 특히 키 하나만으로도 `maxmemory`를 넘을 때는 기존 데이터를 지우지 않고 OOM 에러를 냅니다."
